# MyTeam UI/UX 设计优化与开发规格

> 本文面向下一轮前端开发，基于当前 `app/im-page.tsx` 与 `app/im.css` 的实际界面审查编写。目标是在不改变产品核心能力、不重做品牌风格的前提下，提高可读性、操作安全感、信息效率、移动端体验和可访问性。

## 1. 项目现状与设计判断

MyTeam 当前已经形成明确的产品视觉语言：深蓝主导航、浅灰工作区、蓝色主操作、卡片化内容以及员工专属头像色。桌面端三栏消息结构清晰，通讯录和决策线也已经具备完整的信息骨架。

当前主要问题不是视觉风格缺失，而是以下几类体验债务：

- 大量常用文字只有 9～12px，阅读负担偏高；
- 部分按钮热区只有 25～40px，移动端与高分屏上不够易用；
- 决策线“即时保存”缺少明确反馈，删除操作缺少保护；
- 决策线用串行箭头表达分派，容易被理解为顺序执行；
- 组织架构页右侧详情区留白过多，信息密度不均；
- 桌面表格式配置在手机端被简单压缩，缺少移动端专属结构；
- 部分输入框、图标按钮和弹窗缺少完整的可访问语义。

本轮设计策略：**保留现有品牌和导航结构，优先提升信息可读性、关键操作反馈与跨端适配。**

## 2. 本轮目标

### 2.1 用户目标

用户应能：

1. 快速找到并进入员工或群组对话；
2. 在不担心误操作的情况下配置决策线；
3. 清楚理解调度者与专家之间是“分流关系”而非“串行关系”；
4. 在桌面和手机上都能顺畅查看组织、员工与配置详情；
5. 获得明确的加载、保存、失败、空状态和删除反馈。

### 2.2 可量化目标

- 常用正文不小于 14px；
- 常用控件触控区域不小于 44×44px；
- 所有数据修改都有保存中、成功或失败反馈；
- 所有破坏性操作都有二次确认或可撤销机制；
- 390px 宽度下不出现页面级横向滚动；
- 键盘可以访问主要导航、弹窗、表单与操作按钮；
- 200% 文本缩放下主要任务仍可完成。

## 3. 设计原则

### 3.1 信息优先级

界面只保留三级信息层级：

- 一级：页面标题、员工姓名、主要操作、关键状态；
- 二级：角色、领域、对话摘要、表单标签；
- 三级：时间、数量、说明、Token 等元数据。

不能依赖 9px 字号制造层级。层级应同时通过字号、字重、颜色和间距表达。

### 3.2 操作反馈

任何持久化修改都必须显示状态：

- 未修改：不显示状态；
- 已修改未保存：显示“有未保存的更改”；
- 保存中：按钮显示“保存中…”并禁用重复提交；
- 保存成功：显示短暂的“已保存”；
- 保存失败：保留用户输入并显示可重试错误；
- 离开未保存页面：弹出离开确认。

### 3.3 克制扩展

本轮不新增业务模块，不调整 API 架构，不改变消息发送和员工档案的数据结构。只修改展示、局部交互状态与必要的无障碍语义。

## 4. 全局设计系统调整

### 4.1 字体层级

建议在 `app/im.css` 中增加语义化字体变量：

```css
:root {
  --text-xs: 0.75rem;   /* 12px，仅次要元数据 */
  --text-sm: 0.875rem;  /* 14px，标签与辅助正文 */
  --text-md: 1rem;      /* 16px，主要正文 */
  --text-lg: 1.125rem;  /* 18px，卡片标题 */
  --text-xl: 1.5rem;    /* 24px，页面标题 */
  --text-2xl: 2rem;     /* 32px，大屏页面标题 */
}
```

使用规则：

- 消息气泡、输入内容：14～16px；
- 员工名称、表单内容、常用按钮：14px；
- 角色、时间、数量、状态：12px；
- 页面标题：桌面 28～32px，手机 24～26px；
- 不再使用 9px、10px、11px 作为用户频繁阅读的字号；
- 字体单位逐步从 `px` 改为 `rem`，支持浏览器字号设置。

### 4.2 色彩与对比度

保留当前深蓝、蓝色和浅灰体系，统一为以下语义 Token：

```text
--surface-page      页面背景
--surface-card      卡片背景
--surface-subtle    次级容器背景
--text-primary      主文字
--text-secondary    次级文字
--text-tertiary     非关键元数据
--border-default    默认边框
--action-primary    主操作
--state-success     成功/在线
--state-warning     警告/未保存
--state-danger      删除/失败
```

要求：

- 说明文字与背景的对比度至少达到 WCAG AA；
- 在线/离线、成功/失败不能只通过颜色区分，必须配合文字或图标；
- 删除按钮只在 hover、focus 或明确操作区中使用红色，不把整页染成危险态。

### 4.3 间距与圆角

统一使用 4px 基础间距：4、8、12、16、24、32、48。

- 页面左右边距：桌面 32～56px，平板 24px，手机 16px；
- 卡片内边距：桌面 20～24px，手机 16px；
- 卡片间距：16～20px；
- 主卡片圆角：16px；
- 输入框和按钮圆角：10～12px；
- 小标签圆角：8px 或胶囊形，不混用过多规格。

### 4.4 控件尺寸与焦点

- 主要按钮高度 44px；
- 普通输入框、下拉框高度至少 44px；
- 纯图标按钮视觉尺寸可小于 44px，但点击热区必须达到 44×44px；
- 所有可操作元素增加清晰的 `:focus-visible` 样式；
- disabled 状态除降低透明度外，还需取消阴影并改变鼠标状态；
- loading 状态不得只改变按钮文字，应保留按钮宽度，避免布局跳动。

## 5. 消息页优化

### 5.1 桌面布局

保留 `82px + 360px + 内容区` 的三栏结构，但建议：

- 1600px 以上将内容居中并保留背景边界；
- 1024～1280px 时会话列表缩至 300～320px；
- 聊天内容最大阅读宽度设为 760～820px，避免长段文字铺满整屏；
- 输入框与消息阅读宽度对齐，形成稳定的内容轴线。

### 5.2 会话列表

- 会话摘要最多显示两行，避免所有内容都被压成一行省略号；
- 时间与未读状态放在右上角，角色作为次级信息保留在底部；
- 选中态增加左侧 3px 蓝色标识或更明确的边框，不能只依赖浅蓝背景；
- 搜索无结果时显示“没有匹配的员工或群组”，并提供清空搜索；
- “群组 0”和“最近对话 4”中的数量统一为徽标样式。

### 5.3 聊天头部

当前“分配任务、员工信息、新对话、删除”同时出现，动作较密集。建议：

- 一级操作：`新对话`；
- 二级操作：`员工信息`、`分配任务`；
- 危险操作：`删除对话`收进“更多”菜单；
- 手机端只显示返回、头像、姓名和更多菜单；
- 删除对话前使用确认弹窗，明确说明只删除当前会话还是清除上下文。

### 5.4 消息内容

- AI 长回答的文本宽度不超过 720px；
- 表格、代码块和图片可以在气泡内部横向滚动，但页面本身不能横向滚动；
- 消息时间由 9px 提升到 12px；
- Token 数量默认弱化，可放入消息详情或 hover 信息；
- 思考过程卡片默认折叠，仅展示步骤状态摘要；
- 错误状态不要使用“点击错误文本关闭”，改为错误提示 + “重试” + 关闭图标。

### 5.5 输入区

- 附件、表情按钮热区调整至 44×44px；
- 表情功能未实现前隐藏按钮，避免产生无反馈操作；
- 输入框获得焦点时显示明显边框与柔和 focus ring；
- 上传中显示文件级进度或统一“正在上传”；
- 发送失败时保留草稿和附件；
- 手机端考虑将 Enter 保留为换行，通过发送按钮提交，避免软键盘误发送。

## 6. 通讯录与组织架构页优化

### 6.1 页面头部

桌面端保留标题、统计和模式状态，去掉重复操作：

- 页面右上角保留唯一的“决策线配置”入口；
- 左侧组织树卡片内部不再出现第二个同名按钮；
- “本地模式/云端同步”显示为带图标的状态标签，并提供解释 Tooltip。

### 6.2 组织树

- 宽度从固定 272px 调整为 280～320px；
- 增加“搜索部门或成员”输入框；
- 部门节点支持折叠，默认展开有成员的节点；
- 当前节点使用背景、文字颜色和左侧标识共同表达选中态；
- 人数为 0 的节点降低视觉权重，但仍保持可操作；
- 底部“调度者”说明改为紧凑状态卡，包含头像、姓名和“查看决策线”。

### 6.3 详情面板

当前详情内容集中在顶部，右侧大面积空白。建议：

- 详情内容最大宽度 960px；
- 部门详情采用两列布局：左侧职责与基本信息，右侧成员；
- 员工详情头部固定展示头像、姓名、角色、在线状态、对话与编辑操作；
- 空部门使用图标、说明和“添加成员”主操作构成完整空状态；
- 仅有一句职责说明时不要拉伸整张大卡片。

### 6.4 员工档案编辑

- 查看态和编辑态视觉上明确区分；
- 编辑态底部增加粘性操作栏：`取消`、`保存档案`；
- 离开编辑态前检查未保存更改；
- Skill 长文本编辑区域增加字符数、保存状态和折叠预览；
- 标签删除按钮使用真正的 `<button>`，不要使用可点击的 `<i>`；
- 年龄字段增加合理范围和错误提示。

## 7. 决策线页面优化

### 7.1 信息架构

页面调整为三部分：

1. 决策线概览；
2. 调度者配置；
3. 专家节点配置。

“使用说明”改为可折叠帮助区，默认收起，减少首屏长度。

### 7.2 决策关系表达

当前 `调度者 → 专家 A → 专家 B → 专家 C` 容易表达成串行流程。应改为：

```text
                 ┌→ 产品专家
用户问题 → 调度者 ├→ 财务专家
                 ├→ 战略专家
                 └→ 其他专家
```

桌面端可用中心节点 + 分支卡片；手机端不要绘制复杂连线，改为：

- 顶部调度者卡片；
- 下方“可分派给”列表；
- 每个专家显示领域与关键词数量。

### 7.3 编辑模型

独立决策线页面统一改为草稿保存，不再对每次键盘输入即时持久化：

- 页面加载后创建本地 draft；
- 修改后显示“有未保存的更改”；
- 页面底部显示粘性保存栏；
- 点击保存后一次提交完整配置；
- 保存成功显示 Toast；
- 保存失败保留 draft；
- 关闭或切换导航时，如存在未保存更改，显示确认弹窗。

原通讯录中的决策线 Modal 应删除或改成只读摘要，避免与独立页面形成两套编辑逻辑。

### 7.4 专家节点

桌面端每个节点使用四列布局：

```text
员工 | 专业领域 | 路由关键词 | 更多操作
```

设计要求：

- 输入框上方显示字段标签，不能只依赖 placeholder；
- 关键词以可编辑 Chip 呈现，支持 Enter 和逗号添加；
- 同一员工重复出现时给出提示，但不强制禁止；
- 关键词为空时显示警告：“该专家暂时无法被自动匹配”；
- 删除收进更多菜单或使用带确认的图标按钮；
- 支持上下移动节点顺序，但本轮不需要拖拽排序。

### 7.5 移动端专家卡片

390px 宽度下，每个节点采用折叠卡片：

```text
┌ 乔布斯                         编辑 ┐
│ 产品设计 · 用户体验                  │
│ 7 个关键词                             │
└──────────────────────────────┘
```

点击“编辑”后进入单卡片编辑态，字段纵向排列。避免在一个手机页面同时展示所有节点的完整输入框。

## 8. 响应式规格

### 8.1 Breakpoint

```text
≥ 1280px：完整桌面布局
821～1279px：紧凑桌面/平板横屏
≤ 820px：移动端布局
≤ 480px：小屏手机细化
```

### 8.2 移动端规则

- 使用底部导航，保持现有三个一级入口；
- 页面底部内容增加安全区与导航高度补偿；
- 弹窗在手机端改为底部 Sheet，最大高度不超过 `90dvh`；
- Sheet 头部和主要操作保持可见，内容区域独立滚动；
- 不使用 hover 承载必要信息；
- 不通过隐藏文字仅保留首字符的 CSS 技巧表达主要操作；
- 组织架构页先显示组织树，选择节点后进入独立详情视图，并提供返回按钮。

## 9. 状态设计

所有核心页面都需要覆盖：

### 9.1 加载状态

- 页面首载：展示与真实布局一致的 Skeleton；
- 消息回复：保留现有思考动画，并提供员工姓名；
- 保存：按钮内 loading，不清空输入。

### 9.2 空状态

- 没有会话：引导选择员工或新建群组；
- 没有搜索结果：显示清空搜索；
- 部门没有成员：显示添加成员；
- 决策线没有专家：显示添加第一个专家；
- 员工没有 Skill：查看态保持简洁，编辑态提供添加入口。

### 9.3 错误状态

- 数据加载失败：说明失败对象并提供重试；
- 保存失败：错误信息靠近保存栏，不丢失 draft；
- 消息发送失败：在对应消息位置显示重试；
- 本地模式：明确说明数据保存在当前浏览器，不使用容易误解为同步成功的文案。

### 9.4 成功状态

使用轻量 Toast，文案具体：

- “决策线已保存”；
- “员工档案已更新”；
- “已将张三添加到产品部”；
- “对话已删除”。

## 10. 可访问性要求

- 搜索框增加可见标签或 `aria-label="搜索员工、部门或群组"`；
- 消息输入框增加 `aria-label="输入消息"`；
- 所有纯图标按钮必须有 `aria-label`；
- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和标题关联；
- 打开弹窗后焦点进入弹窗，关闭后回到触发按钮；
- Escape 可以关闭非破坏性弹窗；
- Tab 顺序与视觉顺序一致；
- 选中导航使用 `aria-current="page"`；
- 在线状态、颜色标签和错误状态均提供文字信息；
- `prefers-reduced-motion` 下关闭非必要动画；
- 点击用的 `<i>`、`<span>` 改为语义化 `<button>`。

## 11. 代码组织建议

`app/im-page.tsx` 已承载过多页面和弹窗。建议在不改变行为的前提下逐步拆分：

```text
app/components/navigation/
  app-sidebar.tsx
  mobile-navigation.tsx

app/components/chat/
  conversation-list.tsx
  chat-header.tsx
  message-list.tsx
  message-composer.tsx

app/components/organization/
  organization-tree.tsx
  organization-detail.tsx
  employee-profile.tsx

app/components/decision-line/
  decision-line-overview.tsx
  decision-line-editor.tsx
  expert-node-card.tsx

app/components/feedback/
  confirm-dialog.tsx
  toast.tsx
  empty-state.tsx
  skeleton.tsx
```

拆分原则：先抽纯展示组件，再抽交互组件，最后抽数据 hooks。不要在本轮同时重写数据层。

## 12. 推荐实施顺序

### Sprint UI-1：基础可读性与无障碍

1. 建立字体、颜色、间距和控件尺寸 Token；
2. 将常用文字提升到 14px，元数据提升到 12px；
3. 将常用控件热区提升到 44×44px；
4. 补充 input、button、dialog 的 ARIA 与 focus-visible；
5. 隐藏未实现的表情按钮；
6. 不改变页面信息架构。

### Sprint UI-2：决策线重构

1. 将概览改为调度者向专家分流的视觉结构；
2. 独立页面采用 draft + 显式保存；
3. 增加保存状态、失败重试、离开确认；
4. 删除重复配置入口与重复编辑 Modal；
5. 专家节点增加标签、关键词 Chip、空关键词警告和删除确认。

### Sprint UI-3：通讯录与移动端

1. 优化组织树和详情区空间分配；
2. 增加组织搜索和节点折叠；
3. 手机端组织详情采用两级页面；
4. 手机端专家节点改为折叠卡片；
5. 完善 Sheet、空状态和错误状态。

### Sprint UI-4：聊天细节与组件拆分

1. 调整聊天头部操作优先级；
2. 优化长消息、错误、附件与输入区；
3. 删除操作增加确认；
4. 逐步拆分 `im-page.tsx`；
5. 完成视觉回归和跨端测试。

## 13. 验收清单

### 13.1 视觉验收

- [ ] 1440×900 下三个一级页面不存在明显无效空白或内容挤压；
- [ ] 1024px 下三栏消息页面仍可正常使用；
